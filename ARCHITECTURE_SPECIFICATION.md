# DocuExplain AI — Architecture & XAI Mathematical Specification

## 1. System Overview

**DocuExplain AI** is an enterprise-grade document intelligence platform designed to eliminate generative AI hallucinations through **Retrieval-Augmented Generation (RAG)** coupled with an **Explainable AI (XAI)** mathematical attribution layer.

---

## 2. Core Mathematical Formulation of Explainable AI (XAI)

Every generated answer is evaluated across 4 orthogonal dimensions to compute a calibrated **Confidence Score ($C \in [0, 1]$)**:

### 2.1 The Confidence Calibration Matrix:
$$C = w_1 \cdot S_{\text{max}} + w_2 \cdot S_{\text{avg}} + w_3 \cdot \text{Coverage} + w_4 \cdot \text{Consistency}$$

Where:
- $S_{\text{max}}$: Peak cosine similarity among retrieved top-$k$ vector chunks:
  $$S_{\text{max}} = \max_{i \in \{1 \dots k\}} \cos(\mathbf{q}, \mathbf{d}_i) = \max_{i} \frac{\mathbf{q} \cdot \mathbf{d}_i}{\|\mathbf{q}\| \|\mathbf{d}_i\|}$$
- $S_{\text{avg}}$: Mean cosine similarity of top-$k$ evidence chunks:
  $$S_{\text{avg}} = \frac{1}{k} \sum_{i=1}^{k} \cos(\mathbf{q}, \mathbf{d}_i)$$
- $\text{Coverage}$: Lexical & conceptual overlap between query intent tokens $T_q$ and evidence passage tokens $T_e$:
  $$\text{Coverage} = \frac{|T_q \cap T_e|}{|T_q|}$$
- $\text{Consistency}$: Inverse variance across evidence passages to measure inter-chunk agreement:
  $$\text{Consistency} = 1.0 - \min\left(1.0, \sqrt{\frac{1}{k} \sum_{i=1}^{k} (\cos(\mathbf{q}, \mathbf{d}_i) - S_{\text{avg}})^2}\right)$$
- Default weights calibrated to:
  $$w_1 = 0.45, \quad w_2 = 0.25, \quad w_3 = 0.20, \quad w_4 = 0.10 \quad \left(\sum w_i = 1.0\right)$$

### 2.2 Confidence Tiers:
- **High Confidence ($\ge 82\%$)**: Strong semantic grounding with high lexical and vector alignment.
- **Moderate Confidence ($60\% - 81\%$)**: Partial direct evidence with inferred context.
- **Low / Guard Triggered ($< 60\%$)**: Insufficient direct grounding.

### 2.3 Strict Anti-Hallucination Fallback:
If $S_{\text{max}} < \theta$ (where threshold $\theta = 0.35$):
The system activates the zero-hallucination safeguard and returns the verbatim fallback:
> *"I couldn't find sufficient evidence in the uploaded documents to answer this question."*

## 3. 7-Stage Document Ingestion Pipeline

```
┌──────────────┐     ┌──────────────────┐     ┌─────────────────┐     ┌────────────────────┐
│ 1. Uploading │ ──> │ 2. Parsing Pages │ ──> │ 3. Text Cleaner │ ──> │ 4. Chunk Generator │
│ (PPT/PDF/DOC)│     │ & Slide Elements │     │ (Unicode Norm)  │     │ (Overlap Semantic) │
└──────────────┘     └──────────────────┘     └─────────────────┘     └─────────┬──────────┘
                                                                                │
┌──────────────┐     ┌──────────────────┐     ┌─────────────────┐               │
│ 7. Ready for │ <── │ 6. ChromaDB      │ <── │ 5. Dense Neural │ <─────────────┘
│ XAI Queries  │     │ Vector Indexing  │     │ SBERT Embedding │
└──────────────┘     └──────────────────┘     └─────────────────┘
```

1. **Format Ingestion**: Multi-modal parsers extract text from:
   - **PowerPoint (`.pptx`, `.ppt`)**: Slide shapes, tables, notes frames, and bullet trees.
   - **PDF (`.pdf`)**: Page-by-page token stream extraction via `pypdf`.
   - **Word (`.docx`, `.doc`)**: Paragraphs, table matrices, and header hierarchies via `python-docx`.
   - **Plain Text (`.txt`, `.md`, `.csv`, `.rtf`)**: Direct character encoding with UTF-8 fallback.
2. **Text Normalization**: Strips control characters, normalizes whitespace, and preserves punctuation.
3. **Semantic Chunking**: Overlapping sliding window (500 characters, 100 character overlap) while preserving exact page number metadata.
4. **Vector Embeddings**: 384-dimensional dense vectors generated by `all-MiniLM-L6-v2` SentenceTransformers.
5. **ChromaDB Vector Store**: Isolated per-user persistent vector collections.
